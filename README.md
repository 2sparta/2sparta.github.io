# Класний простір

Шкільна платформа: вхід, школи, розклад, завдання, оцінки, оголошення, чат.

Дані й акаунти зберігаються у **Firebase** (проєкт `schooleballs`): Authentication + Cloud Firestore. Власний сервер і Postgres не потрібні.

## Локально

```bash
npm install
npm run dev
```

## Хостинг

Залийте сайт на Firebase Hosting, GitHub Pages або Vercel (команда збірки `npm run build`).

У Firebase Console → Authentication → Settings → Authorized domains додайте адресу сайту. Без цього вхід з нової адреси не спрацює.

Після входу учень може натиснути «Відкрити демо як Максим». Учитель створює школу — клас 8-А уже заповнений.

## Самоврядування, чергування та додаткові матеріали

### Корисне → історична мапа

Вкладка «Корисне» у додаткових матеріалах відкриває атлас 395–1453 з детальною Візантією, світом та Руссю-Україною. Є часова шкала з кроком один рік, введення року, 11 кнопок картографічних зрізів, режими «Русь-Україна», «Візантія», «Європа», «Світ», масштабування й переміщення, шари територій/міст/регіональних осередків/річок, пошук, картки та вибір території з клавіатури. Рік і режим зберігаються в URL; «Поділитися» копіює посилання. «Головна» повертає стандартне меню.

**Рік подій і дата геометрії показані окремо.** Історичні контури доступні для 500, 600, 700, 800, 900, 1000, 1100, 1200, 1279, 1300, 1400 років. Для проміжного року використовується найближчий зріз (за однакової відстані — раніший), без інтерполяції кордонів. Міські й регіональні картки використовують обраний рік. Це навчальна реконструкція, а не перевірена карта точних щорічних кордонів.

Регіональний шар: 34 міські/регіональні позначки, 37 подій, 10 періодів і 42 бібліографічні записи. Джерела: Encyclopedia of Ukraine / CIUS, Інститут історії України НАНУ, Harvard MAPA, первинний текст Йордана через Fordham, Metropolitan Museum, Columbia, Палац великих князів Литовських. Перша згадка міста не прирівнюється до заснування; кільця регіонів — точки-орієнтири, не точні територіальні межі. До IX ст. показано попередні спільноти, не «державу Україна». Враховано дискусійний каганат у зрізі 800, узагальнення князівств у 1200, відсутність окремої Галицько-Волинської геометрії у 1279/1300 та агрегування Польщі й ВКЛ у 1400. Литовський союз не названо Річчю Посполитою до 1569. Сині Води та Калка не мають удавано точних бойових маркерів.

Мапи, берегова основа та річки постачаються локально в `public/atlas`; немає запитів до сервісу тайлів, API-ключів або нових колекцій Firestore. Leaflet завантажується тільки на клієнті. Карти: Historical Basemaps, pinned commit `da7a4b735ecef70aebdc9c73e409d8a2500d50f3`, оригінальна GPL-3.0 збережена поруч із похідними даними; фізична основа Natural Earth 5.1.2 — public domain. `NOTICE.md` і `manifest.json` містять походження, перетворення й контрольні суми. Береги та русла — сучасні орієнтири, не реконструйовані середньовічні. Дані спрощено на 0,02°; це не заява про історичну точність.

Для повторюваної підготовки даних: `node scripts/build-historical-atlas.mjs` (потрібен інтернет; не входить до звичайної збірки). Перевірки мап і джерел входять до `npm run test:school-tools`.

### Детальна Візантія

39 картографічних зрізів з наданого користувачем архіву карт Lucius: 395–1453. Візантія використовує останній доступний зріз **не пізніше обраного року**; огляд світу — найближчий з попередніх 11 зрізів. Точні річні межі не вигадуються. У 395–499 та 1401–1453 інші країни ще не налаштовані й показані нейтральним суходолом. Це не означає відсутності держав. 1453 — стан **до захоплення Константинополя 29 травня**; 1204 та 1261 мають окремі пояснення переходу між доступними картами.

Детальні векторні кордони замінюють лише відповідні оглядові полігони Візантії/Трапезунда. Інші геометрії не змінено. Після 1204 Нікея, Епір/Фессалоніка та Трапезунд розрізняються, пізніше також Феодоро. Є 12 довідкових міст: їхні маркери не стверджують безперервного візантійського володіння. Феми, внутрішні межі та авторські назви збережені в окремому **растровому авторському шарі**, не перетворені на окремі інтерактивні адміністративні одиниці. Палітра мапи наслідує джерело: білі землі, блакитні моря, рожеві імперські володіння, сині річки, класичні підписи.

Метод: контрольні перетини градусної сітки → конічна геоприв’язка для шести груп проєкції → суміщення інших кадрів за синіми берегами/річками → приглушення друкарських позначень лише в копії для виділення заливки → трасування кольорових областей → GeoJSON WGS84. Звичайний лінійний перерахунок прямокутника PNG у широту/довготу не застосовано. Похідні контури спрощено на 1,25 пікселя оригіналу. Дрібні острови, вузькі володіння та межі під текстом можуть мати артефакти: оригінал є контрольним джерелом, а мала похибка прив’язки сітки не означає історичної точності кордонів.

Геометрія та перепроєктовані авторські зображення постачаються локально в `public/atlas/byzantium` (~29 МБ загалом; растри завантажуються лише після ввімкнення шару). Перегляд оригіналу в повній роздільності завантажує PNG із сайту автора; є масштабування, прокручування й пряме посилання. Власні контрольні точки, параметри, відкинуті вимірювання, матриці суміщення, SHA-256 завантажених джерел та похідних файлів — у manifest/config. ©Lucius; його карти не позначено GPL або CC. Ліцензія GPL попереднього оглядового набору залишається окремою.

Для відтворення: встановіть офлайн-залежності підготовки з `scripts/atlas/requirements.txt`, розпакуйте надані PNG, виконайте `python scripts/build-byzantine-atlas.py /absolute/path/to/PNGs`. Це не входить до звичайної збірки й не змінює API, авторизацію або Firestore. `--reuse-raster` повторно використовує лише файли з відповідними SHA-256. Метадані й геометрію перевіряє `npm run test:school-tools`.

### Інші можливості

- «Самоврядування» → «Комітети та спікер»: пошук учнів за ім’ям/класом, перегляд поточної посади, одночасне збереження призначення й бюджету. Один учень — одна посада; перехід звільняє попередню. Особисті бали не змінюються. Конфлікт паралельного редагування показує помилку, а не перезаписує нове призначення.
- Розклад → таблиця чергових: кнопка редагування, вставка рядків/колонок через «+» на межах, меню рядка (дублювання, переміщення, видалення), скасування/повторення, вставка з Excel, експорт CSV. До 40 рядків і 12 колонок. Старий формат читається; новий зберігає рядки як `{ cells: [...] }`, оскільки Firestore не підтримує вкладені масиви.
- «Додаткові матеріали»: окреме меню «Огляд», «Відео», «Статті», «Корисні посилання». «Головна» повертає стандартну навігацію. Відео YouTube/Vimeo відтворюються на сайті.
- Учні створюють і редагують власні статті; учителі керують усіма матеріалами своєї школи. Батьки читають опубліковані матеріали. Чернетки доступні автору та вчителям. Редактор має форматування, попередній перегляд, локальну резервну копію та перевірку конфліктів.
- Фото з буфера обміну: скопіюйте фото або скриншот, поставте курсор у поле повідомлення й натисніть Ctrl+V / ⌘V. Те саме працює у формах уроків та гуртків. Фото завантажується через наявний сервіс Drive, з’являється в попередньому перегляді й надсилається разом із текстом або без нього. До 4 вкладень; для обкладинки гуртка — 1. Під час завантаження надсилання недоступне. Звичайне вставлення тексту збережено.
- У статтях вставлення фото в поле тексту додає зображення в позиції курсора; кнопка фото також дозволяє вибрати файл. До 20 фото на статтю. Під час завантаження редагування тексту, збереження та публікація тимчасово недоступні. Зображення видно в попередньому перегляді та опублікованій статті; небезпечні URL не відображаються. Буфер має містити файл зображення, а не лише посилання на нього.
- Статті → «Стиль тексту»: заголовок і підзаголовки 1–4, а також звичайний текст. Стиль застосовується до поточного або виділених рядків без втрати тексту. Зміст формує ієрархію всіх п’яти рівнів і посилання на розділи; повторювані назви мають окремі якорі.
- «Вставити віджет» відкриває форму: автоматичний зміст; сторони конфлікту (2–4 сторони, учасники, командувачі, сили, втрати, дата, місце, результат); інформаційна картка (до 12 характеристик); хронологія (до 20 подій із переміщенням); примітка, порада або попередження. Віджет додається після поточного рядка. У тексті він має іменований блок ⟦…⟧; його дані змінюються через «Редагувати» у списку під текстом. Видалення — у цьому ж списку. Перегляд і опублікована стаття показують готові віджети. Віджети зберігаються всередині наявного поля body: нові правила Firestore та міграція не потрібні.
- Таблиця чергових: меню «…» у кожному заголовку колонки дозволяє дублювати її з даними, перемістити ліворуч/праворуч або видалити. Діють ліміт 12 колонок, заборона видалити останню, підтвердження видалення даних, скасування/повторення та збереження всієї таблиці.

### Перед увімкненням нових функцій

**Оновіть правила Firestore з `firestore.rules` у Firebase Console → Firestore Database → Rules → Publish.** Додані колекції `materials` і `officeAssignments` закриті старими правилами. До публікації правил сайт показуватиме помилку доступу для цих функцій. Комітети беруть поточні призначення зі `students`: ручна міграція даних не потрібна.

Для нового розділу додаткові складені індекси не потрібні: запити фільтрують лише рівність, а пошук/сортування виконуються на клієнті.

Перевірки моделі й буфера обміну: `npm run test:school-tools`. Перевірка правил на локальному емуляторі: `npm run test:firestore` (вкажіть `FIRESTORE_EMULATOR_HOST=127.0.0.1:8185` для іншого порту). Можна запустити Firebase CLI: `firebase emulators:exec --config tests/firebase.json --only firestore --project demo-school-tools "npm run test:firestore"`. Інтеграційні сценарії для тестового проєкту: два одночасні призначення на одну посаду; учень читає чужу публікацію, але не чужу чернетку; інша школа не читає матеріали; одночасна зміна таблиці або статті повертає CONFLICT.

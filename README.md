# Класний простір

Шкільна платформа: вхід, школи, розклад, завдання, оцінки, оголошення, чат.

Дані й акаунти зберігаються у **Firebase** (проєкт `schooleballs`): Authentication + Cloud Firestore. Власний сервер і Postgres не потрібні.

## Локально

```bash
npm install
npm run dev
```

## Хостинг

Залийте сайт на Firebase Hosting, GitHub Pages або Vercel (команда збірки `npm run build`).

У Firebase Console → Authentication → Settings → Authorized domains додайте адресу сайту. Без цього вхід з нової адреси не спрацює.

Після входу учень може натиснути «Відкрити демо як Максим». Учитель створює школу — клас 8-А уже заповнений.

## Самоврядування, чергування та додаткові матеріали

- «Самоврядування» → «Комітети та спікер»: пошук учнів за ім’ям/класом, перегляд поточної посади, одночасне збереження призначення й бюджету. Один учень — одна посада; перехід звільняє попередню. Особисті бали не змінюються. Конфлікт паралельного редагування показує помилку, а не перезаписує нове призначення.
- Розклад → таблиця чергових: кнопка редагування, вставка рядків/колонок через «+» на межах, меню рядка (дублювання, переміщення, видалення), скасування/повторення, вставка з Excel, експорт CSV. До 40 рядків і 12 колонок. Старий формат читається; новий зберігає рядки як `{ cells: [...] }`, оскільки Firestore не підтримує вкладені масиви.
- «Додаткові матеріали»: окреме меню «Огляд», «Відео», «Статті», «Корисні посилання». «Головна» повертає стандартну навігацію. Відео YouTube/Vimeo відтворюються на сайті.
- Учні створюють і редагують власні статті; учителі керують усіма матеріалами своєї школи. Батьки читають опубліковані матеріали. Чернетки доступні автору та вчителям. Редактор має форматування, попередній перегляд, локальну резервну копію та перевірку конфліктів.

### Перед увімкненням нових функцій

**Оновіть правила Firestore з `firestore.rules` у Firebase Console → Firestore Database → Rules → Publish.** Додані колекції `materials` і `officeAssignments` закриті старими правилами. До публікації правил сайт показуватиме помилку доступу для цих функцій. Комітети беруть поточні призначення зі `students`: ручна міграція даних не потрібна.

Для нового розділу додаткові складені індекси не потрібні: запити фільтрують лише рівність, а пошук/сортування виконуються на клієнті.

Перевірки моделі: `node --experimental-strip-types --test tests/school-tools.test.ts`. Перевірка правил на локальному емуляторі: `npm run test:firestore` (вкажіть `FIRESTORE_EMULATOR_HOST=127.0.0.1:8185` для іншого порту). Можна запустити Firebase CLI: `firebase emulators:exec --config tests/firebase.json --only firestore --project demo-school-tools "npm run test:firestore"`. Інтеграційні сценарії для тестового проєкту: два одночасні призначення на одну посаду; учень читає чужу публікацію, але не чужу чернетку; інша школа не читає матеріали; одночасна зміна таблиці або статті повертає CONFLICT.

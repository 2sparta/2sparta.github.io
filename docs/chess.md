# Шаховий клуб

Розділ відкривається в «Корисне → Шахи» за адресою `/app/materials?section=useful&tool=chess`.

## Можливості

- Гра з локальним ботом на трьох рівнях та гра вдвох на одному пристрої. Рокіровка, взяття на проході, вибір фігури при перетворенні, шах, мат і нічиї обробляються chess.js. Локальна партія зберігається на пристрої окремо для облікового запису. Дошка обмежена по ширині. Під час локальної практики видно взяті фігури, матеріальну перевагу, приблизну оцінку, одну підказку ходу й копіювання FEN. Підказка не вмикається в онлайн-партії.
- 3 865 дебютних варіантів Lichess CC0, пошук за назвою/ECO/ходами, 12 навчальних пояснень українською й англійською, покрокова дошка та перехід до гри або аналізу. Це каталог ходів, а не статистика партій.
- Аналіз PGN або FEN, власні продовження, три кандидати на хід, оцінка з боку білих, експорт PGN. Локальний навчальний рушій виконує обмежений alpha-beta пошук у Web Worker; його оцінки наближені. Це не Stockfish і не виміряний рейтинг Elo. Поточна онлайн-партія не передається в аналіз.
- Відкриті запрошення для своєї школи або всіх зареєстрованих користувачів сайту, посилання/код партії, спостереження, серверні годинники з додаванням часу, здача й пропозиція нічиєї.
- Колові турніри на 2–16 учасників, реєстрація, автоматичні пари з чергуванням кольорів, пропуск туру для непарної кількості, турнірна таблиця й збережені партії. Виграш 1, нічия ½, поразка 0; додатковий показник — кількість перемог. За однакових показників місце спільне. Шкільні бали не змінюються.

## Активація онлайн-частини

Локальні режими та дебюти працюють у звичайній збірці сайту. **Онлайн-партії й турніри потребують розгортання доданого Firebase backend**; самої публікації статичних файлів недостатньо.

Із кореня репозиторію, для наявного проєкту `schooleballs`, під обліковим записом із правами розгортання:

```sh
npm ci
npm ci --prefix functions
firebase deploy --project schooleballs --only functions:chess,firestore:rules,firestore:indexes
```

`firebase.json` запускає збірку функції перед розгортанням. Кодова база `chess` експортує callable-функцію `chessAction` у `europe-west1`, Node.js 22. Admin SDK отримує облікові дані середовища Firebase; приватні ключі не зберігаються в репозиторії чи браузері. Треба дочекатися готовності індексів Firestore. Інші Cloud Functions проєкту не належать цій кодовій базі.

Predeploy пакує спільну шахову модель у `functions/dist/index.cjs`. Порожній `gcp-build` вимикає повторну збірку в Cloud Build, де немає вихідних файлів клієнтського проєкту; у хмару надсилається вже готовий пакет. Див. [Node.js Buildpacks](https://docs.cloud.google.com/docs/buildpacks/nodejs).

Авторизація використовується та сама, що й на сайті. Сервер бере UID з перевіреного Firebase Auth контексту та школу з профілю; UID, школа, час, FEN, результат або учасники, підставлені в запиті браузера, не можуть підмінити ці дані. Нові колекції: `chessGames`, `chessTournaments`, `chessLimits`. Прямий запис браузером заборонено, включно з власними партіями й турнірами. Шкільні кімнати читають учасники своєї школи; загальні — авторизовані користувачі. Власні партії залишаються доступними гравцю після зміни школи.

Кожен хід проходить повторне відтворення історії та транзакцію з перевіркою ревізії. Приєднання до вільного місця й реєстрація також транзакційні. Мат, пат і автоматичні нічиї обчислюються сервером; клієнт не подає власний результат. Контроль часу: 3+2, 5+3, 10+0, 15+10. Годинники стартують при приєднанні суперника; в турнірі — одразу при запуску туру організатором. При відключенні час продовжує йти. Учасник може перевірити прострочення годинника, організатор — завершити тур із простроченими партіями. Відсутність фонової функції не дозволяє зробити пізній хід: перевірка часу виконується перед прийняттям ходу.

Запрошення живуть 15 хвилин. Створення нових запрошень обмежене інтервалом 5 секунд, турнірів — 60 секунд. Партія обмежена 600 півходами; навчальний клуб автоматично фіксує нічию при триразовому повторенні й правилі 50 ходів. У турнірі організатор може закрити реєстрацію або запустити наступний тур лише після завершення поточного. Активні турніри не можна довільно скасувати чи вручну підмінити їхній результат.

## Перевірки

```sh
npm run typecheck
npm run build
npm run test:chess
npm run test:chess-ui
npm run test:chess-interactions
npm run test:chess-interactions-ui
npm run test:chess-service
npm --prefix functions run typecheck
npm --prefix functions run build
```

Емуляторні перевірки: запустити Firestore Emulator на `127.0.0.1:8185`, потім:

```sh
FIRESTORE_EMULATOR_HOST=127.0.0.1:8185 GCLOUD_PROJECT=demo-chess npm run test:chess-rules
```

Цей тест перевіряє правила й запускає **зібраний callable handler** із Admin SDK проти емулятора: приватність, заборона підробок, одночасні приєднання/ходи, реальні транзакції та повний турнір. Контексти користувачів тестові; production Auth перевіряє платформа callable functions. Тестові користувачі й партії не створюються в робочому Firebase.

Джерела дебютів та контрольні суми: `public/chess/openings-manifest.json`. Відтворення: `node scripts/build-chess-openings.mjs`. Атрибуція й ліцензії: `public/chess/NOTICE.md` та `CHESS-JS-LICENSE.txt`.

## Дошка й керування

У «Дошка та налаштування гри» можна обрати три власні SVG-набори фігур («Класичні», «Клубні», «Мінімальні»), три кольори дошки, координати, підказки легальних ходів, виділення останнього ходу та автоматичне перетворення на ферзя. Класичні фігури мають звичні силуети; зображення Chess.com не використовуються. Параметри зберігаються на пристрої.

Премуви працюють проти бота й у власній активній онлайн-партії. Під час ходу суперника можна обрати **один** попередній хід. Фіолетове виділення та повідомлення показують чергу. Після відповіді суперника клієнт перевіряє актуальну позицію, а онлайн-сервер повторно перевіряє хід і ревізію. Нелегальний премув скасовується; він не змінює годинник і не отримує окремого часового бонусу. Вибір фігури при перетворенні підтримується й для премувів.

Скасування: Esc, права кнопка миші, повторний дотик до виділеної клітинки або «Скасувати премув». Перехід до історії, зміна партії, повернення ходу, нова гра та вимкнення премувів також очищують чергу. Премуви не зберігаються між відкриттями сторінки.

Права кнопка миші ставить коло; перетягування правою кнопкою — стрілку. Shift змінює колір на червоний, Alt — на синій. На телефоні ввімкніть «Позначки», торкніться клітинки або протягніть стрілку. Повторна однакова позначка видаляється. «Очистити позначки» чи нова позиція очищує дошку. Позначки локальні й не надсилаються супернику.

У списку ходів клавіші ← / →, Home / End переміщують позицію. На самій дошці стрілки клавіатури переміщують фокус між клітинками.
